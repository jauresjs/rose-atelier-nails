# English and French

The initial language comes from the browser’s `Accept-Language` preferences, including regional variants such as `fr-CA` and quality weights. The User-Agent string is used for installation-device instructions only; it does not reliably carry language preferences. Unsupported languages fall back to English. The EN/FR selector saves an explicit one-year `rose-language` cookie, which takes priority over browser preferences. The server selects the language before rendering, sets the HTML language and Content-Language header, and prevents caching across users.

French copy is written for the product’s warm, conversational voice using “tu.” UI labels, accessible names, account feedback, gallery/poll screens, installation guidance, dates, and exported story captions are localized. User-entered descriptions and poll titles remain unchanged. Underlying shape and finish values retain the model’s existing identifiers. AI inspiration is instructed to write its names, summaries and prompts in the selected language; model output is not guaranteed and was not billed during localization checks. Email templates remain managed in Supabase and are not automatically translated by this app.

`src/lib/locales/fr.json` holds French copy. `src/lib/i18n.ts` handles language negotiation, copy lookup, and variable allowance messages. Run the normal check/build, then `node scripts/verify-language.mjs` for server language negotiation, SSR, persistent choice and CSRF checks. Real device interactions require ARTEMIS exploration before authoring mobile test code.
