# Sharing and plans

Choose four saved designs created today (UTC) in Gallery, title the poll, and publish. Only those four images become public. The poll link supports anonymous voting without installation or registration. One vote per browser cookie is enforced atomically; it is not a guarantee of one vote per person. Results refresh every 2.5 seconds while the page is visible. The creator can close the poll, after which new votes are rejected atomically.

Prepare four 1080×1920 story images, then use the device share sheet or save each image. Instagram/Snapchat require the user to add the copied poll URL as a link sticker. The web app cannot insert that sticker automatically. Native sharing and installed-device flows still need actual device verification; server integration checks do not simulate these.

Generation UI requires standalone PWA display. The server requires a client-reported standalone header, which can be forged; browsers provide no trusted installation attestation. Guests get one generation per browser cookie, with an additional two guest attempts per network per UTC day. Signing in transfers the guest design and usage to the verified account. Free accounts get five attempts/day and Premium twenty/day, resetting at midnight UTC. Official downloads require authentication; visible preview pixels can still be saved through browser tools or screenshots.

Reservations are atomic and count before contacting FAL. Definite rejected submissions are refunded; uncertain submissions stay counted to avoid repeated provider charges. One active generation per owner is allowed. The studio-wide cap defaults to 250 generation attempts/day (`DAILY_STUDIO_LIMIT` can override). Inspiration has persistent limits: guest three lifetime, Free twenty/day, Premium forty/day, studio-wide one thousand/day, and a ten-second cooldown. These caps are not a billing guarantee: users may create multiple accounts or browser profiles.

Premium authorization comes only from server-controlled Supabase `app_metadata`: `rose_plan: premium` and a future ISO date in `rose_premium_until`. No price or paid checkout has been configured. For manual test activation, use the Supabase admin-only `scripts/set-premium.mjs` utility with environment credentials, account UUID and expiry date. It preserves other app metadata. Never expose a service-role key to the app or browser. A paid launch needs a checkout provider, price and verified subscription webhooks that update/revoke these entitlements.

Server verification: build then run `node scripts/verify-auth.mjs`. It creates temporary confirmed Supabase users, deletes them in `finally`, uses all generated migrations in SQLite and an in-memory R2 interface, and does not call paid generation models. It checks auth, quotas, races, guest ownership, public polls, duplicate votes, private image isolation and poll closure. Mobile test code must be based on ARTEMIS exploration per the workspace instructions.
